How the data is collected

Every orbit, measurement and picture on this site comes from NASA and ESA. Small programs on GitHub fetch it on a schedule, check it, and publish it here. This page shows how, and what they are doing right now.

How to read this

The light beside each job: green, up to date; brass with rings, updating now; amber, late or one source failing; red, the last update failed. In every case except a first-ever run, the site keeps showing the last good data, so a red light never means wrong numbers on the page.

Last check is when the job last ran; new data is when it last found something new and saved it. A job that checks and finds nothing new saves nothing, so new data can be older than the last check.

The bars are the job's latest runs, oldest on the left: green finished, red failed, grey cancelled, brass running now. Times are in your own time zone.

The path

From the agencies to this page

  1. Fetch. On its schedule, a job on GitHub asks NASA's and ESA's services for the latest data, with no visitor waiting and no key on the page.
  2. Check. Every new file is checked before it is saved: it must read, have rows, not be empty and not suddenly shrink. A file that fails is thrown away.
  3. Save. Only data that changed is saved, in one record with a plain description, so every update can be traced.
  4. Publish. GitHub Pages republishes the site a minute or two later, and the new data is on every page.
  5. Watch. Each job records how every source went. A daily health check reports any job that stops, runs late or fails.

Safeguards

When something goes wrong

NASA's and ESA's services are sometimes down for maintenance, change a format, or answer slowly. The jobs are built so that none of this ever leaves a gap or a wrong number on the site.

  • The last good copy stays. A source that cannot be read keeps its previous data, and the other sources of the same job are still updated.
  • Nothing half-made is saved. A file that does not read, is empty or shrinks to a fraction of its size is put back to its last good version.
  • Two runs a day. Daily data is fetched twice, hours apart, so one late or missed run changes nothing.
  • A daily health check. Every afternoon, every job is checked: still switched on, run recently, every source working. Anything wrong is reported to the developer the same day.

Mars data is slower by nature

NASA publishes the rovers' measurements in batches, months after they are taken. The job checks twice a week and adds a batch soon after it appears.

Some data never changes

The stars, the constellations and the list of towns come from fixed catalogues and are built once.

Open to check

Every update is a public record on GitHub ↗, with what changed and when.

And you

Nothing about you is collected

The data collected here is about space and Earth, never about visitors: no accounts, cookies, analytics or tracking. To show this page's live status, your browser reads GitHub's public list of the site's data runs; the answer is kept in this browser tab for 3 minutes. The details are on the Privacy page.
